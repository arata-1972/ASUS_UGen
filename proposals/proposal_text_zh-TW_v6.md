## 2. 接待現場需要的是下一句能聽懂

情境假設：來訪者問報到位置，職員確認預約姓名

來訪者平常使用台語，接待人員使用華語。
雙方需要確認「在哪裡報到」「預約名字是什麼」「在哪裡等」。
一方說完，另一方要能看懂、聽懂，再接著回答。
目標是減少反覆詢問與意思誤解；尚未量測導入效果。
此為驗證中的使用情境，不是已導入客戶案例。

## 3. 先確認原文，再把意思傳給對方

音檔 → 辨識 → 本人修正 → 翻譯 → 語音

1　選台語或華語，上傳 WAV；按下辨識後才送出。
2　查看原文，修正姓名、地點或聽錯的內容。
3　翻成另一種語言，必要時再修改譯文。
4　產生對方語言的語音，播放或再聽一次。
5　另一方切換語言，用相同流程回覆。
現版為音檔上傳，尚未加入麥克風錄音。

## 4. 實際操作畫面：確認譯文並播放語音

本機瀏覽器介面；推論由已設定的自架服務執行

實際本機畫面：譯文確認與播放區域，見提案 PDF 第 4 頁。

## 5. 辨識錯誤不隱藏，由使用者修正

示範輸入是 Taigi TTS 合成台語，不是真人錄音

輸入文字：「請問服務台佇佗位?」
實際 ASR：「請問服務代到位去。」
本人修正：「請問服務台佇佗位？」
實際翻譯：「請問服務台在哪裡?」→ 全角標點修正後產生華語語音。
畫面保留原文與譯文，修正後才送下一階段。
這個示範呈現錯誤與補正，不代表已通過辨識品質評估。

## 6. 目前架構：本機介面連接自架語音服務

ASR、EOLE 翻譯與 TTS；不需要 LLM

本機瀏覽器：選台語／華語，指定 WAV 音檔
本機 Node 介接：送往設定的自架 ASR 服務
使用者：確認與修正辨識原文
自架 EOLE 翻譯：翻成另一種語言，再確認與修正
自架台語／華語 TTS：產生音訊，瀏覽器播放或下載

## 7. 本次實際畫面展示：修正後聽到華語譯文

合成台語問題 → 實 ASR → 本人修正 → 翻譯 → 華語 TTS

問題：「請問服務台佇佗位？」
華語：「請問服務台在哪裡？」
畫面顯示 ASR 約 803 ms、翻譯約 189 ms、TTS 約 1,147 ms。
成功生成並實際播放華語音訊；未驗證瀏覽器下載存檔。
時間是單次 API 操作，含網路，且不包含本人修正時間。
既有 CLI 連線測試與此接待示範分開記錄，均非 UGen 實機效能。
